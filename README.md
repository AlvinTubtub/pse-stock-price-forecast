# ForecastPH — PSE Stock Price Forecast Dashboard

Educational next-session closing-price forecasts for 15 PSE-listed companies, generated by an
automated ML pipeline and served by a static Next.js dashboard.

**Live Dashboard:** [https://pse-stock-price-forecast.vercel.app/](https://pse-stock-price-forecast.vercel.app/)

This repository combines the Python forecasting pipeline and the Next.js frontend into a single
repository, so a single commit updates both the pipeline output and the deployed frontend.

```text
pse-stock-price-forecast-dashboard/
├── .github/workflows/     # Fast Pipeline (daily) + Heavy Training (weekly) — see backend/README.md
├── backend/                # Python data/ML pipeline — see backend/README.md
│   ├── data/, models/, prediction_cache/, services/, scripts/
│   ├── run_pipeline.py
│   ├── best_models.json, latest_processed.json, statistical_tests.json
│   └── requirements-fast.txt, requirements-pipeline.txt
└── frontend/                # Next.js 14 dashboard — see frontend/README.md
    ├── public/forecasts/    # generated by backend/scripts/export_forecast_artifacts.py
    ├── src/
    ├── package.json
    └── next.config.js, tailwind.config.ts, tsconfig.json
```

- **`backend/`** — scrapes PSE EOD disclosures, cleans/validates data, engineers features, trains
  three forecasting models (Lag-Informed Regression, ARIMA, LSTM) against a naive baseline,
  evaluates them (RMSE/MAE/MASE/R², plus a cross-model statistical-significance suite), and picks a
  winner per ticker. Full detail, including the exact model methodology, in
  [`backend/README.md`](backend/README.md).
- **`frontend/`** — a static Next.js dashboard that reads `frontend/public/forecasts/*.json` and
  renders the home dashboard, company list, per-company detail pages, and the model-performance
  comparison page. No Python, no API routes, no database. Full detail in
  [`frontend/README.md`](frontend/README.md).
- **`.github/workflows/`** — `update_pipeline.yml` (Fast Pipeline, Monday-Friday) and
  `train_models.yml` (Heavy Training, weekly) both run the relevant `backend/` steps, then
  `backend/scripts/export_forecast_artifacts.py`, then commit anything changed under `backend/`
  together with `frontend/public/forecasts/` in the same commit.

## Why one repo now

With `backend/` and `frontend/` as two separate GitHub repos, a pipeline commit only updated
`backend/`'s own copy of the forecast JSON — nothing pushed that data into the frontend repo, so the
live site could silently go stale until someone manually re-synced the two. Merging them into one
repo means the pipeline's commit *is* the frontend's data update: `frontend/public/forecasts/` and
`backend/data/raw/` (etc.) land in the same push, and Vercel's own Git integration (Root Directory
set to `frontend/`) redeploys on every push to `main` — no Vercel Deploy Hook, no PAT, no cross-repo
sync step required anymore.

## Deploying

- **Vercel**: import this repo, set **Root Directory** to `frontend/`. That's the only
  monorepo-specific setting. See [`frontend/README.md`](frontend/README.md) for the rest.
- **GitHub Actions**: nothing to configure beyond the secrets the pipeline already used
  (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`) and the external Cron-job.org trigger for the Fast
  Pipeline — see [`backend/README.md`](backend/README.md#automated-pipeline).
