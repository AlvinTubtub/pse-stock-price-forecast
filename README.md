# ForecastPH — PSE Stock Price Forecast Dashboard

Educational next-session closing-price forecasts for selected Philippine Stock Exchange (PSE)-listed companies, generated by an automated machine-learning pipeline and presented through an interactive Next.js dashboard.

**Live Dashboard:** https://pse-stock-price-forecast.vercel.app/

## Overview

ForecastPH combines a Python-based data and machine-learning pipeline with a static Next.js frontend.

The system:

* Collects and processes PSE end-of-day market disclosures.
* Maintains historical OHLCV data for each tracked company.
* Engineers technical and time-series features.
* Trains and evaluates multiple forecasting models.
* Selects the best-performing model for each company.
* Generates next-session closing-price forecasts.
* Performs cross-model statistical significance testing.
* Exports forecast and market-data artifacts as JSON.
* Presents the results through an interactive web dashboard.

The frontend is read-only. It does not run Python, perform model inference, access a database, or call a backend API. It reads the generated JSON artifacts committed by the automated pipeline.

## Key Features

### Forecasting

The forecasting pipeline compares:

* Lag-Informed Regression
* ARIMA
* LSTM
* Naive previous-close baseline

The models predict next-session **ΔClose**:

`ΔClose(t+1) = Close(t+1) − Close(t)`

The predicted change is then reconstructed into the forecasted price:

`Predicted Close(t+1) = Close(t) + Predicted ΔClose(t+1)`

Model performance is evaluated using:

* RMSE
* MAE
* MASE
* R²

The pipeline also performs cross-model statistical testing using:

* Diebold-Mariano testing
* Harvey-Leybourne-Newbold correction
* Friedman rank testing
* Holm-adjusted Wilcoxon signed-rank tests
* Best-model consistency analysis

## Automated Pipeline

The project uses two automated workflows.

### Fast Pipeline

**Schedule:** Monday-Friday, 4:00 PM Philippine Time

The Fast Pipeline:

1. Downloads new PSE EOD reports.
2. Extracts market data.
3. Cleans and validates the data.
4. Updates the OHLCV CSV files.
5. Updates pipeline metadata.
6. Exports the latest frontend JSON artifacts.
7. Commits changed data artifacts when necessary.
8. Allows Vercel to automatically redeploy from the updated commit.

The Fast Pipeline runs:

```bash
python backend/run_pipeline.py --no-train
```

It does **not** retrain the forecasting models.

### Heavy Training

**Schedule:** Sunday, 8:00 AM Philippine Time

The Heavy Training workflow:

1. Uses the latest available OHLCV datasets.
2. Retrains all forecasting models.
3. Evaluates the models.
4. Selects the best model for each ticker.
5. Runs the statistical significance suite.
6. Updates prediction caches and model metadata.
7. Exports updated frontend artifacts.
8. Commits changed model and forecast artifacts.
9. Allows Vercel to redeploy automatically.

Training can also be executed locally with:

```bash
cd backend
python -m services.model_selector
```

The training workflow is intentionally separated from the daily data pipeline because the complete training process is substantially more computationally expensive.

## Model Evaluation

The models are evaluated against a naive previous-close baseline.

Metrics include:

| Metric | Purpose                                                         |
| ------ | --------------------------------------------------------------- |
| RMSE   | Measures the square-root average magnitude of prediction errors |
| MAE    | Measures average absolute prediction error                      |
| MASE   | Measures error relative to a naive forecasting baseline         |
| R²     | Measures explained variance                                     |

The pipeline also evaluates whether differences between models are statistically meaningful rather than relying solely on individual metric rankings.

## Local Development

### Backend

From the repository root:

```bash
pip install -r backend/requirements-fast.txt
```

For the complete ML stack:

```bash
pip install -r backend/requirements-pipeline.txt
```

Run the complete local pipeline:

```bash
python backend/run_pipeline.py
```

Run data processing without model training:

```bash
python backend/run_pipeline.py --no-train
```

Process already downloaded reports:

```bash
python backend/run_pipeline.py --no-download
```

Specify a date range:

```bash
python backend/run_pipeline.py --start-date 2026-07-01 --end-date 2026-07-27
```

Train models without running ingestion:

```bash
cd backend
python -m services.model_selector
```

Refresh frontend artifacts:

```bash
python backend/scripts/export_forecast_artifacts.py
```

From the repository root:

```bash
cd frontend
npm install
```

Open:

```text
http://localhost:3000
```

The repository contains:

```text
.github/workflows/update_pipeline.yml
.github/workflows/train_models.yml
```

The workflows are responsible for:

* Automated data updates
* Weekly model training
* Forecast artifact generation
* Model-performance artifact generation
* Historical data updates
* Committing generated artifacts
* Triggering normal Vercel Git deployments

The Fast Pipeline uses an external Cron-job.org trigger for its weekday schedule.

The Heavy Training workflow uses GitHub Actions scheduling.

Required pipeline secrets include:

```text
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
```

The Cron-job.org GitHub authentication token must remain stored in Cron-job.org and must never be committed to the repository.

## Data Integrity and Idempotency

The pipeline is designed to safely handle repeated runs.

Key protections include:

* Date-based OHLCV upserts
* Duplicate prevention
* Data validation
* Empty-data checks
* Artifact verification
* Git staged-diff checks
* No-op behavior when nothing has changed

A successful run with no new market data does not create an unnecessary commit.
